# 위키독스 「클로드 코드 멀티에이전트 팀 자동화 완성 가이드」 검토

출처: https://wikidocs.net/347754 (사이드바 64페이지 전부 열어 본문을 확인). 서비스 파이프라인을 개선하는 근거로만 쓴 것이고, 책의 환경(tmux·Redis·원격 제어)을 그대로 들여오지는 않았다. 우리 서비스는 서버 코드(`pipeline.py`)가 LLM 호출을 직접 오케스트레이션하므로 책이 풀려는 문제 중 일부는 구조상 생기지 않는다.

**적용** = 코드·문서에 반영 / **해당 없음** = 서비스 구조상 불필요 / **보류** = 가치는 있으나 이번에 안 함

## 책에서 가져온 설계 원칙 요약

1. **결과 형식을 통일한다**: 평가·QA·재확인은 모두 JSON 스키마로 주고받아 취합을 결정론적으로 만든다.
2. **소수 경고 우선**: 한 평가자가 critical을 말하면 다수가 괜찮다고 해도 고친다.
3. **위임 프롬프트에 맥락을 직접 담는다**: 수정 요청에 원래 과업·내 결과·고칠 것·지킬 것을 모두 넣는다.
4. **완료 기준을 먼저 정한다**: 편성 때 `done_when`을 정해 QA가 그 기준으로 확인한다.
5. **리더는 직접 하지 않는다**: 총괄은 QA를 거친 결과만 받아 종합하고, 미해결은 숨기지 않고 밝힌다.
6. **리뷰어는 고치지 않는다**: 평가자와 QA는 읽고 판단만 하고, 수정은 해당 전문가가 한다.
