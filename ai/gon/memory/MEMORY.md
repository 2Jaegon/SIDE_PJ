# Gon 장기 메모리

사용자 선호, 프로젝트 결정, 교정받은 점. 한 줄에 하나, 틀린 것은 고치거나 지운다. 비밀번호·API 키·개인 식별 정보는 쓰지 않는다.

- [2026-10-28] 사용 가능한 AI는 Claude와 Gemini(Google AI Pro 구독). Gemini는 API 키 대신 Antigravity CLI `agy -p`로 구독 안에서 쓴다.
- [2026-10-28] Munder Difflin 앱은 쓰지 않는다. 상용 앱 복제 대신 직접 만드는 방향.
- [2026-10-28] Gon 저장소: https://github.com/2Jaegon/Gon.git (SkillBridge 제품 저장소와 분리).
- [2026-10-29] 프로젝트 전체(에이전트 + 서비스)를 Gon으로 부른다. 저장소를 통째로 내려받아 `/gon`하면 에이전트 적용과 서비스 실행이 되는 것이 목표. 서비스 이름도 Gon.
- [2026-10-28] GitHub 저장소는 완성 전까지 SIDE_PJ로 두고, 완성되면 Gon으로 이름을 바꾼다(기존 2Jaegon/Gon은 그때 정리). 그 시점에 README의 git clone 주소도 같이 바꾼다.
- [2026-10-28] 스킬 선택은 키워드 매칭이 아니라 AI가 요구사항을 분석해 직접 고른다(gon catalog → gon pick). 서비스 총괄의 전문가 편성도 AI가 하고, 키워드는 AI 응답 실패 시 대체로만 쓴다.
- [2026-10-28] 화면에는 프로젝트와 상관없는 장식 기능(커피 바, 화분, 효과음, 'Gemini 연동' 표시 등)을 넣지 않는다. 사무실에서는 전문가가 입구에서 걸어 들어와 책상에서 일하고, 끝나면 총괄에게 보고하러 걸어가는 움직임을 실제 진행 상태에 맞춰 보여 준다.
- [2026-10-29] 사용자는 agency-agents·OpenMontage·trail-code·codebase-memory-mcp 같은 외부 도구를 Gon이 업무에 맞으면 적극 활용하길 원한다(예: 직무별 페르소나로 릴스 기획, 영상 제작, 학습 노트). 단 외부 코드는 읽고 확인한 뒤 설치하고, 비용이 드는 실행(영상 생성 등)은 견적을 먼저 보여 준다. 2026-10-29 기준 agency-agents만 레지스트리에 등록했고 나머지 셋은 이 PC에서 설치 흔적이 없다.
- [2026-10-29] 개발 스펙은 FastAPI, React+TypeScript, Supabase가 고정이고 그 밖의 도구·라이브러리는 자유롭게 써도 된다(사용자 지시). user/.env에 Supabase 연결 문자열(DATABASE_URL) 및 인증 API가 연동되어 있으며 [YOUR-PASSWORD] 미입력 시 로컬 SQLite 폴백으로 동작한다.
- [2026-10-29] 화면 구조는 피그마 Desktop-1(1440x1024) 기준이다: 왼쪽 사이드바(접으면 접기 버튼 없이 로고를 눌러 펼침), 오른쪽 위 3D 사무실(바닥에는 전문가 책상만, 정면에서 기울기만 있는 직교 시점이고 사용자가 마우스 휠 버튼을 누른 채 위아래로 끌어 조절한다. 슬라이더는 지웠다), 아래 왼쪽 대화·오른쪽 총괄 자리. 총괄 자리는 대화와 분리된 별도 카드이고 사무실 카드 바닥에 맞붙으며, 3D 총괄 책상은 그 카드의 자리 창 맨 아래에 붙어 사무실 쪽을 보고, 사무실 바닥에서 그 바닥까지 길(바닥)이 끊기지 않게 이어진다. 총괄 인물과 카드 머리글·'요청을 분석해…' 안내 문구는 없고, 책상 뒤에 로고와 '총괄 Gon'만 놓인다. 전문가는 총괄 자리에서 걸어 나와 책상에서 일하고, 끝나면 이어진 길로 총괄 책상 앞(사무실 쪽)에 서서 전달한 뒤 돌아온다. 총괄 자리를 사무실 바닥이나 대화 줄에 합치지 않는다(사용자가 두 번 바로잡음). 사무실에는 입구가, 채팅 아래에는 '직접 고르기'가 없다(전문가는 빈 책상의 + 로 고른다). 로고는 어두운 정사각 바탕의 흰색 ] 모양이며 원본 파일이 없어 이미지를 보고 SVG로 다시 그렸다(user/frontend/src/components/Mark.tsx).
- [2026-10-29] UI 작업에서는 `gon pick`으로 고른 디자인 스킬을 실제로 읽고 그 절차(검색·검사 스크립트 실행)를 따르며, 브라우저로 직접 화면을 열어 확인하면서 진행한다. 사용자가 "스킬을 전혀 활용하지 않는 것 같다", "브라우저 스킬로 직접 확인하라"고 지적했다. 외부에서 바이너리를 내려받는 도구(impeccable 검사기 등)는 실행 전에 사용자에게 묻는다.
