# Engineering Minimalism & GSD Rules

본 워크스페이스의 코드 작성 및 아키텍처 작업 시 아래 규칙을 강제 적용합니다 (출처: `andrej-karpathy-skills`, `gsd-core`, `ECC`):

1. **First-Principles & 가독성:**
   - 문제를 해결할 수 있는 가장 단순하고 직관적인 코드를 먼저 작성한다.
   - 불필요한 레이어(오버엔지니어링, 복잡한 디자인 패턴, 불필요한 래퍼 함수)를 피한다.
2. **실천주의 (Get Stuff Done):**
   - 가상의 계획에 멈추지 말고 실제 실행 가능하고 테스트 가능한 파일 단위로 작업한다.
   - 변경 후에는 빌드/실행 가능 여부를 점검한다.
3. **코드 청결성:**
   - 함수는 단일 책임을 갖고 50줄 이내를 지향한다.
   - 변수명과 함수명은 축약하지 않고 그 자체로 역할을 설명하도록 짓는다.
4. **보안 및 환경 변수:**
   - API 키, 토큰, 비밀번호는 절대 코드에 하드코딩하지 않고 `.env`를 통한다 (`.gitignore` 보호).
